01

这个项目在做什么

在化学实验室里，用两个摄像头和几个传感器盯着实验台，发现"人走了还在加热""烧杯快烧干了""没戴护目镜""冒烟了"这类危险，提前提醒；真到危险时，自动切断加热电源。

一个场景
  1. 小王在用电热板加热烧杯里的水，中途出去接电话。全景摄像头发现实验台没人了，小屏变黄，提示"加热中无人值守，60 秒后自动断电"，喇叭提醒。
  2. 水烧开了，温度停在 100℃ 左右。系统知道水还在，只提醒"沸腾中，请留意液面"。
  3. 水烧干了，温度越过 100℃ 继续上升。系统马上算出"约 15 秒后达到 120℃"，再次提醒。
  4. 温度到了 120℃（或者无人值守超时），系统让控制盒切断加热电源，小屏整屏变红。
  5. 小王回来，确认安全后，必须亲手按控制盒上的复位键才能重新通电。

和普通监控的区别：普通监控是出事后能回放，我们是出事前就提醒，来不及就断电。

温度预测是怎么想的（答辩常被问）

  • 烧杯里还有水时，温度到 100℃ 左右就会停住，不会再涨。所以温度没到沸点时，系统只预测"多久后沸腾"，不会喊"要烧干了"。
  • 温度越过沸点还在涨，说明水已经没了。这时根据最近 15 秒的升温速度，算出"多久后到 120℃"，提前提醒。
  • 一直在沸腾、人又不在：沸腾时间越长风险分越高，到 5 分钟也会提醒。
  • 预测只用来提醒，不会因为预测就断电。断电只看实际温度和规则。

下位机自己的规则

不依赖开发板，开发板死机也照样执行：

什么情况结果
加热片 ≥ 150℃断电
烟雾 ≥ 2500断电
30 秒收不到开发板的心跳，而且还在加热断电
刚上电继电器默认断开
一个识别结果要在 3 秒内六成以上的画面都成立才算数，避免某一帧看错就乱报。同一件事解除后 10 秒内又出现，算作同一次，不会反复刷屏、反复播报。

为什么"软件只能断电，不能通电"

%%{init: {"theme":"base","themeVariables":{"primaryColor":"#FFFFFF","primaryBorderColor":"#5C6BC0","primaryTextColor":"#2A3166","lineColor":"#5C6BC0","fontSize":"14px"}}}%%

温度和烟雾}
    Check -->|仍然危险| Refuse[拒绝，蜂鸣器长鸣]

    classDef bad fill:#FFE3E7,stroke:#C62839,color:#8E1B2A

断电是安全的方向，谁都可以按；通电是危险的方向，必须有人在现场亲眼确认。所以：

  • 程序里根本没有"通电"的接口，有测试专门检查这一点。
  • 安全助手（大模型）连断电都不能做，它只能看、只能给建议。大模型可能说错话，所以不让它碰任何开关。
  • 复位键按下后，下位机还会再检查一遍温度和烟雾，危险没解除就拒绝通电。

三条线路，自动选能用的那条

线路需要什么适合
远程（通义千问）能上网 + 一个 DashScope API Key效果最好
本地（Ollama）一台装了 Ollama 的电脑，和开发板在同一个 Wi-Fi现场没网时
规则模板什么都不需要兜底，保证断网也有建议

配置远程 Key

  1. 在阿里云百炼（DashScope）控制台申请 API Key。
  2. 二选一：在开发板或电脑上设置环境变量 DASHSCOPE_API_KEY 后启动程序；或者在网页「安全助手」页的"远程 API Key"框里填（只存在内存里，重启要重新填）。
  3. 点「测试远程」，显示"在线"就好了。
Key 千万不要写进 config.yaml，也不要提交到 GitHub。

配置本地 Ollama

1. 在电脑上安装 Ollama，下载模型：

ollama pull qwen2.5:7b

2. 网页「安全助手」页把"本地地址"改成 http://电脑的局域网IP:11434/v1，保存，点「测试本地」。

隐私：默认不会把事件截图发给远程 API，只发文字描述。需要的话在页面上勾选"允许把抓拍图发给远程 API"。助手引用的安全手册在 labguard/knowledge/实验室安全手册.md，每个"## 标题"是一条，可以按学校的实验室制度修改。

在自己电脑上跑起来

先安装 Python 3.10–3.12（安装时勾选 "Add Python to PATH"）。

第 1 步　打开终端，进入源码文件夹

cd labguard

第 2 步　安装依赖（只需要做一次）

pip install -r requirements.txt

第 3 步　启动（电脑大窗口 + 网页大屏）

python run_app.py

终端会打印一行"总后台已启动……口令 XXXXXX"。浏览器打开 http://127.0.0.1:8080，输入这个口令。口令也保存在 runtime/web_token.txt。

想在电脑上看小屏界面

python run_app.py --mode edge --windowed

跑测试（改完代码后一定要跑，两个都显示"全部通过"才算没改坏）

python tests/test_backend.py
python tests/test_platform.py

三种运行模式

命令显示用在
python run_app.py电脑大窗口 + 网页电脑开发、演示
python run_app.py --mode edge小屏全屏 + 网页开发板正式运行（开机自启用的就是它）
python run_app.py --mode headless只有网页开发板没接屏幕时

没有硬件时怎么演示

  1. 启动程序。没有摄像头时，到网页「参数」页的「画面源」选演示视频，点「播放视频」。演示视频放在 labguard/media/ 或仓库根目录的 local_private/ 里（都不会上传 GitHub）。
  2. 到网页「环境控制」页右边的「演示数据」，按顺序点：
    • 正常加热→沸腾：温度从 40℃ 升到 99℃ 停住；
    • 烧干：在 99℃ 停一会儿后继续升温，越过 120℃ 触发断电；
    • 烟雾超标、高湿受潮、环境高温：分别触发对应规则。
  3. 演完点「停止注入」。
没接下位机时，断电是"软件模拟断电"，危险解除 10 秒后自动解锁，方便连续演示。接上真实下位机后，演示数据会被拒绝（真假数据不混用），断电后必须按复位键才能恢复。

常见问题

网页打不开？
看三点：程序有没有在运行；电脑和开发板是不是同一个 Wi-Fi；地址里的 IP 对不对（小屏「设置」页能看到）。
网页提示口令错误？
口令在小屏「设置」页或 runtime/web_token.txt。删掉这个文件再重启，会生成新口令。
画面显示 NO SIGNAL？
摄像头没接好或编号不对。在 config.yaml 的 camera 里改 pano / desk 的编号（0、1、2……），或者先用演示视频。
显示"视觉离线"？
识别模型没加载成功。检查 models/ 文件夹里有没有两个 .pt 文件。
安全助手一直显示"规则模板"？
说明远程和本地都没连上。去网页「安全助手」页分别点「测试远程」「测试本地」看具体原因。断网时用规则模板是正常的。
断电后怎么恢复？
接了下位机：到现场确认安全，长按控制盒上的复位键 1 秒。没接下位机（演示）：危险解除 10 秒后自动解锁。
改了阈值不生效？
网页「参数」页改的立即生效；直接改 config.yaml 要重启程序。网页改过的值保存在 runtime/config_override.yaml，它会覆盖 config.yaml 里的同名项。
测试没通过？
把终端里打印的报错完整发到群里，不要自己删测试。

名词解释

名词意思
YOLO11一种识别图片里物体的模型，我们用它认人身上的装备和台面上的器皿
NPU开发板上专门跑识别模型的芯片，比 CPU 快很多、更省电
RKNN把模型转换成 RK3588 的 NPU 能跑的格式
下位机控制盒里的 ESP32，直接控制硬件；开发板叫"上位机"
继电器用电信号控制的开关，断开后加热片就没电
心跳开发板每秒给下位机发一条"我还在"；断了 30 秒下位机就自己断电
锁定断电后保持断电状态，直到有人按复位键
投票一个识别结果要在 3 秒内六成以上的画面成立才算数，防止误报
温度预测根据最近的温度变化算出多久沸腾、多久烧干
安全助手 / Agent能查资料、给建议的大模型程序，只能看、不能控制设备
通义千问 / DashScope阿里的大模型和它的接口平台（远程线路）
Ollama在自己电脑上运行大模型的软件（本地线路）
V-JEPA 2Meta 发布的视频模型，能预测画面接下来会怎样；预测不准就说明画面里发生了不寻常的事。我们把它作为可选的画面异常检测
口令打开网页大屏要输入的 6 位密码
演示数据没接硬件时，用程序模拟传感器数值，用来演示
